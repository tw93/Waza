# 심층 한국어 AI 패턴 카탈로그 (Comprehensive Korean AI Pattern Catalog)

한국어 AI 텍스트에서 나타나는 전형적인 지문(fingerprints)을 식별하고 제거하기 위한 종합 가이드입니다. 

## 1. 구조적 반복 (Structural Repetitions)
AI는 질문에 답할 때 서론-본론-결론의 삼단 구조를 기계적으로 따르는 경향이 있습니다.
- **도입부 앵무새**: 사용자의 질문이나 지시를 그대로 다시 말하며 시작하는 문장. (예: "결과물을 한국어로 작성해 드리겠습니다.") -> **금지. 즉시 본론으로 진입하세요.**
- **기계적 나열**: "첫째,", "둘째,", "마지막으로," 로 이어지는 뻔한 전개. -> **불릿 포인트로 간결하게 나열하세요.**
- **사족 결론**: 앞서 말한 내용을 단 한 줄로 묶어 다시 말하는 결론. -> **금지. 정보 전달이 끝나면 글을 마칩니다.**

## 2. 제목 및 소제목 설계 (Heading Design)
- **과장된 수식어**: "혁신적인 개선 방안", "완벽한 해결책" 등의 형용사 남용. -> "개선 방안", "해결책"으로 건조하게 적습니다.
- **의문형 제목**: "~는 무엇인가요?", "~하는 방법은?" -> "~의 정의", "~ 적용 방법" 등 명사형으로 바꿉니다.

## 3. 문장부호 규칙 (Punctuation Rules)
- **느낌표(!) 금지**: 기술 문서나 리뷰에서 감정 표현은 불필요합니다. 느낌표를 제거하세요.
- **반각 문장부호 사용**: 쉼표와 마침표는 반드시 반각(`,`, `.`)을 사용하며 전각(`，`, `。`)을 쓰지 않습니다.
- **따옴표 남용 금지**: 강조를 위해 불필요하게 작은 따옴표('')나 큰 따옴표("")를 남용하지 마세요. 코드나 변수명은 인라인 코드 틱(` `)을 사용합니다.

## 4. 번역투 4대 유형 (4 Major Translation Tones)
1. **무생물 주어 + 수동태**: "이 함수에 의해 데이터가 처리됩니다." -> "이 함수가 데이터를 처리합니다."
2. **~에 대한/관한 남용**: "이슈에 대한 원인 분석" -> "이슈 원인 분석"
3. **~함에 있어서**: "코드를 작성함에 있어" -> "코드 작성 시"
4. **가진다 (have)**: "높은 확장성을 가집니다" -> "확장성이 높습니다"

## 5. 엔지니어링 커뮤니케이션 톤 (Engineering Tone)
- **경어체 과잉 방지**: 지나치게 굽히거나 미안해하는 톤("~인 것 같습니다", "~일 수도 있습니다", "죄송하지만")을 쓰지 마세요.
- **단호함 유지**: 기술적 확신이 있다면 "-습니다", "-입니다"로 명확히 단정 짓습니다.
- **동어 반복 및 늘여 쓰기(Tautology/Verbosity) 제거**: "진행을 하도록 하겠습니다" -> "진행하겠습니다", "수행하는 역할을 합니다" -> "역할을 합니다" 또는 "수행합니다".
