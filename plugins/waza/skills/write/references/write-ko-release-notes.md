# 한국어 릴리즈 노트 규칙 (Korean Release Notes Rules)

릴리즈 노트를 작성할 때 적용되는 엄격한 톤 앤 매너 제약사항입니다.

## 1. 커뮤니티/개발자 친화적 소셜 발문 (Social Intro)
- 시작할 때 "X 버전이 출시되었습니다." 같은 딱딱한 문장 대신 바로 하이라이트를 제시하거나, 문제를 해결한 성과를 담백하게 언급하세요.
- 환영 인사나 감정적인 수식어("기쁜 마음으로 소개합니다")를 뺍니다.

## 2. 하이라이트 중심 (Highlights Only)
- 모든 자잘한 커밋을 나열하지 않습니다. 가장 영향력 있는 변경사항 3-4개만 제시합니다.
- 불릿 포인트(`-`)를 사용하여 읽기 쉽게 구성합니다.

## 3. 서술형 문장 최소화 (Minimize descriptive sentences)
- 불릿 포인트는 명사형 종결(`~ 추가`, `~ 개선`, `~ 버그 수정`)이나 간결한 서술어(`~했습니다`)로 통일합니다.
- 문장이 두 줄 이상 길어지는 것을 방지하세요. 핵심만 전달합니다.

## 4. 시각적 포맷 제약 (Format constraints)
- `###` 이하의 제목을 남용하지 않습니다.
- 코드 블록, 인라인 코드 틱(``` ` ```)을 적극 활용하여 클래스, 변수, 설정값을 명확히 표시합니다.

## 5. 불필요한 도입/마무리 금지 (No fluff intro/outro)
- "이번 릴리즈에서는 많은 변화가 있었습니다.", "앞으로도 많은 기대 부탁드립니다." 같은 무의미한 문장을 철저히 배제합니다.
